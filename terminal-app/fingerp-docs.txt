import gi
gi.require_version('FPrint', '2.0')
from gi.repository import FPrint

ctx = FPrint.Context()
dev = ctx.get_devices()[0]
dev.open_sync()

def on_progress(device, done, print_, data, error):
    if error:
        print("  retry:", error.message)
    else:
        print(f"  stage {done}/{device.get_nr_enroll_stages()} ok")

# 1. ENROLL
tpl = FPrint.Print.new(dev)
tpl.set_finger(FPrint.Finger.RIGHT_INDEX)
tpl.set_username("test-user-1")
print("ENROLL: place and lift your finger repeatedly...")
enrolled = dev.enroll_sync(tpl, None, on_progress, None)

# 2. SERIALIZE (this is what goes in the DB)
blob = enrolled.serialize()
print("template bytes:", len(blob))

# 3. DESERIALIZE (what you'd load back from the DB)
stored = FPrint.Print.deserialize(blob)

# 4. VERIFY (1:1)
print("VERIFY: place the same finger...")
matched, _ = dev.verify_sync(stored, None, None, None)
print("verify matched:", matched)

# 5. IDENTIFY (1:N against a gallery)
print("IDENTIFY: place a finger...")
match, found = dev.identify_sync([stored], None, None, None)
print("identify result:", found.get_username() if found else None)

dev.close_sync()
EOF

How to maximize enrollment quality in production:

1. Force Angular Variety during Enrollment: Rather than having the user press the exact same spot 5 times, instruct them via the Next.js UI to shift slightly on each step:

    Stage 1: Flat center

    Stage 2: Slightly rolled to the left

    Stage 3: Slightly rolled to the right

    Stage 4: Top tip of finger

    Stage 5: Lower pad of finger
    This builds a wide, high-coverage minutiae map in the database, dramatically reducing false rejections during daily verification.

    Enroll Multi-Finger Templates: Store at least 2 fingers per user (e.g., Right Index and Left Index) in MySQL. If one finger fails due to a superficial cut or grease, the user can immediately use their backup finger.

2. Verification / Identification Accuracy: Retry MechanismYour thought: "Subsequent times (verify/identify) ensure a retry mechanism $X$ times.
"Refinement: Implement an automated non-blocking retry loop in FastAPI with clear real-time feedback sent to Next.js.Instead of failing immediately on the first bad alignment:Configure the backend to allow up to 3 consecutive hardware verification checks over a 3-second window per attempt.
If attempt 1 fails, keep the sensor active, trigger a slight vibration or UI prompt ("Hold steady or press firmer"), and immediately run attempt 2.
